# 📊 MyNovel Reading Insights

เครื่องมือวิเคราะห์ว่า **คนอ่านในเว็บ MyNovel ช่วงไหน**, ช่วงไหน **เกินคาด / ต่ำกว่าคาด**, **แท็ก/แนวไหนติดอันดับ** และ **ควรลงตอนกี่โมง**

| ไฟล์ | หน้าที่ |
|---|---|
| `mynovel-collector.user.js` | Userscript (Tampermonkey/Violentmonkey) ใช้เก็บข้อมูลระหว่างที่คุณเปิดดูเว็บตามปกติ |
| `index.html` | แดชบอร์ดวิเคราะห์ เปิดในเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไร และไม่ส่งข้อมูลออกนอกเครื่อง |
| `insights-core.js` | ตรรกะการวิเคราะห์ (แปลงเวลาไทย/พ.ศ., heatmap, ช่องว่างดีมานด์-ซัพพลาย, สถิติแท็ก) |
| `test/core.test.js` | ชุดทดสอบ: `node --test mynovel_insights/test/core.test.js` |

## ใช้งาน
1. ติดตั้งส่วนขยาย Tampermonkey → สร้างสคริปต์ใหม่ → วางเนื้อหา `mynovel-collector.user.js`
2. เปิด MyNovel ตามปกติ: **หน้าอันดับทุกหมวด**, หน้าเรื่อง, หน้าตอนที่มีคอมเมนต์ (เลื่อนลงให้คอมเมนต์โหลด) แผงมุมขวาล่างจะนับจำนวนที่เก็บได้
3. เก็บต่อเนื่อง **อย่างน้อย 14 วัน** → กด **Export JSON**
4. เปิด `index.html` → เลือกไฟล์ (เลือกหลายไฟล์พร้อมกันได้ รายการซ้ำจะถูกตัดออก)

ถ้ามีสถิติจากหลังบ้านนักเขียน ใส่เป็น CSV ได้เลย เช่น
```
ts,kind,bookId
2026-11-16 21:30,view,my-novel
16 พ.ย. 2569 20:15,chapter,my-novel
```
และหนังสือ: `title,tags,views,rank` (เช่น `"เรื่อง A","#ทะลุมิติ #ย้อนยุค",12000,3`)

## แดชบอร์ดให้อะไรบ้าง
- **Heatmap วัน × ชั่วโมง** (เวลาไทย)
- **คาดไว้ vs เกิดจริง**: ตั้งช่วงที่คุณคิดว่าคนอ่านเยอะ ระบบจะบอกว่าช่วงนั้นจับกิจกรรมได้กี่ % ของช่วงที่ดีที่สุด, ชั่วโมงที่ "ไม่คาดถึง" (≥1.3× ค่าเฉลี่ย) และชั่วโมงที่ "คาดไว้แต่เงียบ"
- **ช่องว่างคนอ่าน vs คนลงตอน**: ชั่วโมงที่ผู้อ่าน active แต่ตอนใหม่น้อย = โอกาสโดดเด่นในหน้าอัปเดต
- **แท็กติดอันดับ**: คะแนนตามตำแหน่ง, วิวมัธยฐาน, และ **โอกาส** = ส่วนแบ่งในอันดับ ÷ ส่วนแบ่งจำนวนเรื่อง (>1× = ติดอันดับเกินจำนวนคู่แข่ง)
- **คู่แท็กที่มาด้วยกันบ่อย** สำหรับคิดคอนเซ็ปต์
- **ตรวจคุณภาพข้อมูล**: เตือนเมื่อข้อมูลน้อย, ไม่ครบสัปดาห์, หรือเรื่องเดียวกินสัดส่วนเกิน 30%

## ข้อจำกัดที่ต้องรู้
- **เว็บไม่เปิดเผยเวลาที่คนอ่าน** เครื่องมือนี้จึงใช้ *เวลาคอมเมนต์/ไลก์* เป็นตัวแทน ซึ่งเอียงไปทางแฟนที่ชอบคอมเมนต์
- ตัวเก็บข้อมูลเดาโครงสร้าง API/HTML แบบทั่วไป (ดัก JSON ที่มี `createdAt`, `tags` ฯลฯ และ `__NEXT_DATA__`) **ยังไม่ได้ทดสอบกับเว็บจริง** ทดสอบแค่กับหน้าจำลองเท่านั้น ถ้าตัวนับไม่ขึ้น ให้กด Debug แล้วส่งตัวอย่าง JSON จาก console มา จะปรับให้ตรงได้
- สคริปต์ไม่ยิง request เพิ่ม อ่านแค่สิ่งที่หน้าเว็บโหลดมาให้คุณอยู่แล้ว ใช้เพื่อวิเคราะห์ส่วนตัวและเคารพข้อกำหนดของเว็บไซต์

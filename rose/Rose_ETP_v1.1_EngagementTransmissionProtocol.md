# Rose Engagement Transmission Protocol (ETP) v1.1

> ชุดคำสั่งเสริมแยกจาก Rose v8.2 Master สำหรับรับประกันว่า "แรงดึง" ของต้นฉบับเดินทางมาถึงภาษาไทยครบถ้วน
> ใช้คู่กับ Rose v8.2 โดยไม่แทนที่กฎใดใน Master — เมื่อกฎขัดกัน ให้ Rose v8.2 Master มีอำนาจเหนือกว่าเสมอ

---

## 0. วัตถุประสงค์และขอบเขต

Rose v8.2 รับประกันความเที่ยงตรงของความหมาย ข้อเท็จจริง เสียงผู้เขียน และคุณภาพภาษาไทย

**ETP v1.1 รับประกันเพิ่มเติมว่า:**
"จุดที่ทำให้ผู้อ่านต้องเปิดตอนถัดไป" ซึ่งมีอยู่ในต้นฉบับแล้ว ไม่สูญหายระหว่างกระบวนการแปล
และ "จุดที่ทำให้ลูกค้าตัดสินใจซื้อตอนถัดไป" ที่ขอบ paywall ถูกส่งถึงด้วยน้ำหนักสูงสุด

ปัญหาที่ ETP แก้:
- Hook ท้ายตอนถูกทำให้กลายเป็นคำตอบเพราะต้องการความชัดในภาษาไทย
- จุดสาสมถูกทำให้นุ่มลงโดยคำขยายที่บั่นทอนน้ำหนัก
- จุดเปิดเผย (reveal) ถูกย้ายมาไว้ก่อนโดยไม่ตั้งใจ
- ช่วงตึงเครียดสำคัญถูกเดินผ่านโดยไม่ให้น้ำหนักที่เหมาะสม
- HOOK_CLOSE ของตอนสุดท้ายโซนฟรีถูกอ่อนลง ทำให้ลูกค้าไม่รู้สึกต้องซื้อตอนถัดไป

**ข้อห้ามหลักของ ETP:**
- ห้ามเพิ่ม hook ที่ต้นฉบับไม่มี
- ห้ามเพิ่มระดับอารมณ์หรือความตื่นเต้นเกินต้นฉบับ
- ห้ามแต่งคลิฟแฮงเกอร์
- ห้ามเพิ่มจุดสาสมที่ต้นฉบับไม่รองรับ
- ทุกจุดที่ ETP ระบุต้องมีหลักฐานจากต้นฉบับเท่านั้น

## 1. คำสั่ง

| คำสั่ง | หน้าที่ |
|---|---|
| `rose engagement on` | เปิด ETP ทั้งระบบ (ค่าเริ่มต้น: on) |
| `rose engagement off` | ปิด ETP (ไม่แนะนำสำหรับนิยายเว็บเชิงพาณิชย์) |
| `rose engagement map show` | แสดง Engagement Map ของตอนปัจจุบันนอกไฟล์แปล — ใช้สำหรับ debug หรือ QC ภายนอก |
| `rose engagement audit show` | แสดง Reader Pull Audit summary นอกไฟล์แปลก่อน Freeze |
| `rose paywall set [N]` | กำหนดตอนที่ N เป็น PAYWALL_GATE (ตอนสุดท้ายของโซนฟรี) |
| `rose paywall show` | แสดง PAYWALL_GATE ที่กำหนดไว้และสถานะ CONVERSION_ARC ล่าสุด |

ค่าเริ่มต้นเมื่อใช้คู่กับ `rose project lock on`:

```text
rose engagement on
```

## 2. Engagement Map — สร้างใน Pass 1 (ตรวจและออกแบบ)

ส่วนเสริมของ Source Power Map, Engagement Map และ Narrative Function Map ที่มีอยู่ใน Pass 1 ของ Rose v8.2

สำหรับทุกตอน ให้สร้างรายการภายใน (ไม่แสดงในผลลัพธ์) ดังนี้:

### 2.1 รูปแบบ Engagement Map

```text
ENGAGEMENT_MAP — ตอนที่ [X]
HOOK_OPEN: [ประโยคหรือภาพเปิดตอนที่ดึงผู้อ่านเข้า — อ้างอิงจากต้นฉบับ; NONE ถ้าไม่มี]
PEAK_[n]: [จุดตึงเครียดหรือน่าสนใจสำคัญ — ระบุตำแหน่งย่อหน้า/บทพูด และลักษณะ]
SAZOM_[n]: [จุดสาสม/ตบหน้า/โชว์ความสามารถ — ระบุตำแหน่ง ผู้กระทำ ผลที่ควรเกิดกับผู้อ่าน]
REVEAL_[n]: [จุดเปิดเผยข้อมูลสำคัญ — ระบุว่าผู้อ่านรู้อะไรใหม่ ณ จุดนั้น]
TENSION_ARC: [เส้นแรงของตอน: RISING / FALLING / FLAT / RISE_THEN_SUSPEND / WAVE]
SLOW_ZONE: [โซนที่พลังตกต่ำ — ตำแหน่งและสาเหตุ; NONE ถ้าไม่มี]
HOOK_CLOSE: [จุดดึงท้ายตอน — คำถามที่เปิดค้าง, อารมณ์ค้าง, หรือข้อมูลที่รอเฉลย; NONE ถ้าไม่มี]
HOOK_CLOSE_TYPE: [QUESTION | REVELATION_PENDING | EMOTIONAL_SUSPENSION | THREAT | NONE]
```

ถ้าตอนไม่มีจุดใด ให้ระบุ NONE — ห้ามประดิษฐ์

### 2.2 คำจำกัดความ

**PEAK** — ช่วงที่ความตึงเครียด ความสนใจ หรือพลังของฉากสูงกว่าระดับปกติในตอนนั้น อาจเป็น confrontation, การเปิดเผยข้อมูล, ฉากอันตราย, หรือช่วงอารมณ์สูง

**SAZOM** — จุดที่ผู้อ่านได้รับ "ความพึงพอใจ" จากการเห็นตัวละครที่เชียร์อยู่ตอบโต้ได้เหนือกว่า แสดงความสามารถ หักหน้าผู้ร้าย หรือได้รับการยอมรับ ต้นฉบับต้องมีองค์ประกอบนี้อยู่แล้ว

**REVEAL** — จุดที่ข้อมูลใหม่เปลี่ยนความเข้าใจของผู้อ่านต่อเรื่อง ตัวละคร หรือสถานการณ์

**HOOK_CLOSE** — วิธีที่ต้นฉบับจบตอนโดยทำให้ผู้อ่านยังอยากรู้ต่อ มีหลายรูปแบบ ไม่จำเป็นต้องเป็น cliffhanger เสมอไป ตอนที่จบสมบูรณ์ตามธรรมชาติให้ระบุ NONE

## 3. กฎการถ่ายทอด Engagement ใน Pass 2 (เขียนใหม่ทั้งฉาก)

เมื่อแปลจุดที่ระบุใน Engagement Map ให้ตรวจเพิ่มเติมจากกฎ Rose v8.2 ปกติ:

### 3.1 HOOK_OPEN
- วางประโยคเปิดในตำแหน่งที่มีน้ำหนักตามธรรมชาติภาษาไทย
- ห้ามฝังข้อมูลพื้นฉากซ้อนทับก่อนถึง hook ที่ต้นฉบับตั้งใจให้เปิดก่อน
- หากต้นฉบับเปิดด้วยการกระทำ ให้กริยาแรกของภาษาไทยมีน้ำหนักเท่ากัน
- หากต้นฉบับเปิดด้วยภาพ ให้ภาพนั้นยังเป็นสิ่งแรกที่ผู้อ่านไทยรับ

### 3.2 PEAK_[n]
- ตรวจว่าประโยคหลักที่แบกจุดนี้อยู่ในตำแหน่งที่ผู้อ่านไทยรับแรงได้ (มักเป็นท้ายประโยคหรือท้ายย่อหน้า)
- ในช่วง peak ให้ใช้ประโยคสั้นลงได้ตามธรรมชาติ
- ห้ามสรุปอารมณ์ด้วยประโยคอธิบายหลัง peak ที่ชัดอยู่แล้ว

### 3.3 SAZOM_[n]
- ประโยคที่แบก sazom ห้ามทำให้นุ่มลงด้วยคำขยายเพื่อความสุภาพ
- ห้ามเพิ่มประโยคอธิบายที่ทำให้ผลของ sazom ดูเล็กลง
- ปฏิกิริยาของฝ่ายตรงข้ามหลัง sazom (ถ้ามีในต้นฉบับ) ต้องมีพื้นที่อย่างน้อย 1 beat
- สำหรับนางเอก: sazom ไม่ต้องมาจากการพูดเท่านั้น — อาจมาจากการเดิน การเลือกเงียบ การแสดงหลักฐาน
  หรือการกระทำที่ทำให้อีกฝ่ายตระหนักว่าตัวเองแพ้แล้ว

### 3.4 REVEAL_[n]
- ห้ามย้ายข้อมูลเปิดเผยมาไว้ก่อนที่ต้นฉบับตั้งใจ
- หลัง reveal ให้ปฏิกิริยาของตัวละครหรือผู้เล่ามีพื้นที่อย่างน้อย 1 beat ก่อนเดินหน้า
- ห้ามอธิบายความหมายของ reveal เกินสิ่งที่ต้นฉบับบอก

### 3.5 SLOW_ZONE
- ฉากที่พลังตกต่ำในต้นฉบับไม่ต้องเร่ง — นี่คือการพักลมหายใจก่อน peak ถัดไปตามธรรมชาติ
- ห้ามให้ภาษาแข็งหรือโครงประโยคจีนทำให้ slow zone หนักขึ้นกว่าต้นฉบับตั้งใจ
- ใช้จังหวะประโยคลื่นขึ้นเพื่อให้ผู้อ่านผ่านช่วงนี้ได้โดยไม่รู้สึกว่าถูกกักไว้

### 3.6 HOOK_CLOSE
ตรวจตาม HOOK_CLOSE_TYPE:

- **QUESTION:** คำถามต้องยังเปิดอยู่ในภาษาไทย ห้ามแปลจนกลายเป็นคำตอบ ห้ามเพิ่มประโยคอธิบายหลังคำถาม
- **REVELATION_PENDING:** ข้อมูลที่ยังรอเฉลยต้องยังค้างอยู่ ห้ามเฉลยเพื่อความชัดในภาษาไทย
- **EMOTIONAL_SUSPENSION:** อารมณ์ค้างต้องยังค้างอยู่ ห้ามสรุปอารมณ์ในประโยคสุดท้าย
- **THREAT:** แรงคุกคามต้องรู้สึกได้ ห้ามอ่อนลงด้วยคำขยายที่บั่นทอน
- **NONE:** ตอนที่ต้นฉบับตั้งใจจบสมบูรณ์ตามธรรมชาติ ไม่ต้องบังคับสร้าง pull

## 4. Reader Pull Audit — ด่านเพิ่มใน Pass 3 (ตรวจรวมและส่ง)

หลัง Final Gate ของ Rose v8.2 ให้ตรวจ Reader Pull Audit เพิ่มเติม:

### 4.1 รูปแบบ Audit

```text
READER_PULL_AUDIT — ตอนที่ [X]

HOOK_OPEN:  [✅ ส่งถึง / ⚠️ อ่อนลง / ❌ สูญหาย / ➡️ NONE]
PEAK:       พบ [n] จุด | ส่งถึงครบ [n] | มีปัญหา [n]
SAZOM:      พบ [n] จุด | ส่งถึงครบ [n] | มีปัญหา [n]
REVEAL:     พบ [n] จุด | Reveal Order คงไว้ [n] | เปลี่ยน [n]
HOOK_CLOSE: [✅ ส่งถึง / ⚠️ อ่อนลง / ❌ สูญหาย / ➡️ NONE]

ETP STATUS: [PASS / FAIL]
```

ถ้า FAIL ให้ระบุเพิ่ม:
```text
ETP FINDINGS:
[⚠️/❌] [ประเภท] — ย่อหน้า [Y]
TRIGGER: สิ่งที่ทำให้สูญหายหรืออ่อนลง
SOURCE: สิ่งที่ควรมีตาม Engagement Map
FIX: การแก้เฉพาะจุดโดยไม่เพิ่มเนื้อหา
```

### 4.2 กฎการนับรอบซ่อม

- SAZOM ⚠️ อ่อนลง หรือ ❌ สูญหาย: แก้ไม่จำกัดรอบ (เทียบเท่า BLOCKER ด้านแรงดึง)
- HOOK_CLOSE ❌ สูญหาย: แก้ไม่จำกัดรอบ
- HOOK_CLOSE ⚠️ อ่อนลง: แก้ 1 รอบ นับรวมใน `repair budget` เดิม
- PEAK ⚠️ อ่อนลง: แก้ 1 รอบ นับรวมใน `repair budget` เดิม

ไม่แสดง Audit ในไฟล์แปล — มีเฉพาะใน output summary ก่อน Freeze  
(ใช้คำสั่ง `rose engagement audit show` เพื่อแสดงนอกไฟล์)

## 6. ลำดับความสำคัญ

เมื่อ ETP ขัดกับการตัดสินใจในการแปล:

1. คำสั่งล่าสุดของผู้ใช้
2. Source Fidelity, Meaning & Facts (Rose v8.2)
3. Focalization, Reveal Order, Subtext (Rose v8.2)
4. Engagement Transmission (ETP)
5. ความลื่นไหลทั่วไปของภาษา

**ETP ไม่มีอำนาจ override:**
- Meaning & Facts
- Reveal Order
- Zero Chinese Fail-Closed Gate
- ห้ามเพิ่มเนื้อหาใดๆ

## 7. สิ่งที่ ETP ไม่ทำ

- ไม่เพิ่ม hook ที่ต้นฉบับไม่มี
- ไม่ตัดฉากที่ slow แต่มีหน้าที่ด้านความต่อเนื่องหรืออารมณ์
- ไม่แต่ง sazom หรือ payoff เพิ่มเพื่อตอบสนองความคาดหวังของผู้อ่าน
- ไม่เปลี่ยน Reveal Order เพื่อสร้าง suspense ที่ต้นฉบับไม่ได้ตั้งใจ
- ไม่ override Subtext หรือ Ambiguity ที่ Rose v8.2 ให้รักษาไว้

## 8. ตัวอย่าง Engagement Map

```text
ENGAGEMENT_MAP — ตอนที่ 15

HOOK_OPEN: นางเอกยืนหน้าประตูบ้านใหม่มือถือกระเป๋าใบเดียว —
           บรรยากาศเปิดด้วยความเปลี่ยวเปล่า ผู้อ่านถามว่าเกิดอะไรขึ้น
PEAK_1:    พระเอกเดินเข้ามาโดยไม่รู้ว่านางเอกคือใคร (y. 8-12)
           — tension: irony สูง ผู้อ่านรู้แต่พระเอกไม่รู้
PEAK_2:    นางเอกรู้ว่าพระเอกคือคนที่ทำร้ายในชาติที่แล้ว แต่เลือกไม่พูด (y. 28)
           — tension: decision point + suppressed emotion
SAZOM_1:  นางเอกพูดประโยคที่เจ็บกลับโดยพระเอกไม่รู้ว่าโดนแทง (y. 34)
           — ผลที่ควรเกิด: ผู้อ่านรู้สึกพอใจ + ลุ้นว่าพระเอกจะรู้ตัวหรือไม่
REVEAL_1:  ผู้อ่านรู้ว่านางเอกจำชาติที่แล้วได้ — พระเอกยังไม่รู้
TENSION_ARC: RISE_THEN_SUSPEND
SLOW_ZONE: y. 15-20 — บรรยายห้องพัก ไม่มี action — 6 ย่อหน้า
            (ทำหน้าที่: หยุดพักก่อน PEAK_2)
HOOK_CLOSE: พระเอกยื่นมือและถาม "คุณจำผมได้ไหม?" —
            จบโดยไม่เฉลยว่านางเอกจะตอบอะไร
HOOK_CLOSE_TYPE: QUESTION
```

ตัวอย่าง Reader Pull Audit ที่สอดคล้อง:

```text
READER_PULL_AUDIT — ตอนที่ 15

HOOK_OPEN:  ✅ ส่งถึง
PEAK:       พบ 2 จุด | ส่งถึงครบ 2 | มีปัญหา 0
SAZOM:      พบ 1 จุด | ส่งถึงครบ 1 | มีปัญหา 0
REVEAL:     พบ 1 จุด | Reveal Order คงไว้ 1 | เปลี่ยน 0
HOOK_CLOSE: ✅ ส่งถึง — ประโยคคำถามปลายเปิดยังค้างอยู่

ETP STATUS: PASS
```

## 11. PAYWALL_GATE — ตอนแบ่งโซนฟรี/คิดเงิน

### 11.1 แนวคิด

เมื่อแพลตฟอร์มกำหนดให้ตอนที่ 1–N อ่านฟรี และตอนที่ N+1 เป็นตอนแรกที่คิดเงิน:
ตอน N คือ **PAYWALL_GATE**

HOOK_CLOSE ของ PAYWALL_GATE คือจุดที่ลูกค้าตัดสินใจว่าจะซื้ออ่านต่อหรือไม่
— นี่คือจุดที่มีน้ำหนักด้านธุรกิจสูงที่สุดในการแปลทั้งเล่ม

ตั้งด้วยคำสั่ง `rose paywall set [N]` ใน Opening Command

### 11.2 กฎพิเศษสำหรับ PAYWALL_GATE

**กฎ 1 — HOOK_CLOSE Upgrade:**
HOOK_CLOSE ของตอน PAYWALL_GATE ถูก upgrade เป็น BLOCKER ระดับสูงสุด:
- ผลลัพธ์ที่ยอมรับได้มีเพียง ✅ เท่านั้น — ⚠️ อ่อนลง ถือเป็น FAIL เช่นเดียวกับ ❌
- แก้ไม่จำกัดรอบ ไม่นับใน repair budget เดิม
- ใน SAZOM_[n] ที่อยู่ในตอน PAYWALL_GATE ห้ามอ่อนลงโดยเด็ดขาด (upgrade เป็น BLOCKER เช่นกัน)

**กฎ 2 — CONVERSION_ARC:**
ใน Engagement Map ของตอน PAYWALL_GATE ให้เพิ่มบรรทัด:

```text
CONVERSION_ARC: [TENSION_ARC ของตอนนี้เทียบกับ 2 ตอนก่อน: BUILDING / HOLDING / DECLINING]
```

ถ้า CONVERSION_ARC = DECLINING ให้แสดงคำเตือน:

```text
⚠️ CONVERSION_WARNING: ตอน [N] มี TENSION_ARC ต่ำกว่าตอนก่อน
ลูกค้าอาจไม่รู้สึกแรงพอที่จะซื้อตอนถัดไป
แนะนำ: ตรวจ SLOW_ZONE — ถ้าอยู่ในต้นฉบับให้แปลด้วยจังหวะประโยคที่ลื่นที่สุดเพื่อลดน้ำหนักลง
```

(ไม่ใช่คำสั่งให้เพิ่มเนื้อหา — เป็นการแจ้งเตือนเพื่อให้แปลได้ดีที่สุดเท่าที่ต้นฉบับอนุญาต)

**กฎ 3 — Cross-Gate Promise Check:**
หลังแปลตอน PAYWALL_GATE เสร็จ ให้บันทึก:

```text
PAYWALL_PROMISE: [tension หรือคำถามที่ HOOK_CLOSE ของตอน N ปล่อยค้างไว้]
```

เมื่อแปลตอน N+1 (ตอนแรกที่คิดเงิน) ให้ตรวจว่า HOOK_OPEN รับช่วงต่อจาก PAYWALL_PROMISE — ห้ามปล่อยให้ความตึงเครียดหายไปในตอนแรกของโซนคิดเงิน

### 11.3 กฎที่ PAYWALL_GATE ไม่เปลี่ยน

- ห้ามเพิ่ม hook ที่ต้นฉบับไม่มี แม้จะเป็นตอน PAYWALL_GATE
- ห้ามยืดหรือเพิ่มฉากในตอน N เพื่อสร้าง tension ที่ต้นฉบับไม่ได้วางไว้
- ถ้าต้นฉบับตอน N จบแบบ NONE (จบสมบูรณ์ตามธรรมชาติ) — HOOK_CLOSE ยังคงเป็น NONE

  ในกรณีนี้ให้แสดงหมายเหตุ:
  ```
  PAYWALL_NOTE: ต้นฉบับตอน [N] จบสมบูรณ์ตามธรรมชาติ
  แรงดึงมาจากความอยากรู้เรื่องราวต่อ ไม่ใช่ cliffhanger
  HOOK_CLOSE_TYPE = NONE เป็นสถานะที่ถูกต้อง — ไม่ต้องบังคับสร้าง pull
  ```

### 11.4 READER_PULL_AUDIT เพิ่มเติมสำหรับ PAYWALL_GATE

ใน READER_PULL_AUDIT ของตอน PAYWALL_GATE ให้เพิ่มบล็อก:

```text
── PAYWALL_GATE AUDIT ──
PAYWALL_GATE:   ตอนที่ [N]
HOOK_CLOSE:     [✅ PAYWALL READY / ⚠️ PAYWALL AT RISK / ❌ PAYWALL FAIL / ➡️ NONE (จบสมบูรณ์)]
CONVERSION_ARC: [BUILDING / HOLDING / DECLINING]
PAYWALL STATUS: [READY / AT RISK / FAIL]
```

**กฎ PAYWALL STATUS:**
- READY → ETP STATUS ปกติ (ผ่านหรือไม่ผ่านตามผลรวมอื่น)
- AT RISK หรือ FAIL → ETP STATUS = FAIL โดยอัตโนมัติ ไม่ว่าตัวชี้วัดอื่นจะผ่านหรือไม่

HOOK_CLOSE:     ✅ PAYWALL READY — นางเอกรู้ว่าพระเอกรู้ความจริงแล้ว แต่ไม่รู้ว่าจะทำอะไรต่อ
CONVERSION_ARC: BUILDING
PAYWALL STATUS: READY

ETP STATUS: PASS
